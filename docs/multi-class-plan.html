云函数核心变更
引入 getCallerClassId 安全层，所有查询基于此值过滤

核心安全函数

JavaScript 所有云函数复用此工具函数 
// 从调用者 openid 获取所属班级 ID，不信任前端传入的 classId
async function getCallerClassId(db, openid) {
  const res = await db.collection('users').doc(openid).get()
  if (!res.data) throw new Error('USER_NOT_FOUND')
  if (!res.data.classId) throw new Error('USER_NOT_IN_CLASS')
  return res.data.classId
}

// 使用示例：所有云函数开头统一调用
exports.main = async (event) => {
  const { OPENID } = cloud.getWXContext()
  const classId = await getCallerClassId(db, OPENID)

  // 后续所有查询带上 classId 过滤
  const incomes = await db.collection('incomes')
    .where({ classId, yearTerm })
    .get()
}

迁移策略（零停机）
全程增量操作，旧版本在迁移期间仍可正常使用，可随时回滚
1
创建 classes 集合记录
在 classes 集合创建一条记录，代表现有的唯一班级。将原 classSettings 的数据（className, yearTerm, feePerStudent 等）迁移过来，记录生成的 LEGACY_CLASS_ID。
纯增量，不影响线上
2
批量为所有现有记录添加 classId
遍历 users、classAdmins、classMembers、incomes、expenses、feeSubmissions、specialFunds 共7个集合，为每条记录添加 classId = LEGACY_CLASS_ID。分页处理，每批20条，避免超时。
约30分钟完成，线上不中断
3
发布新版小程序
新版云函数引入 getCallerClassId 安全层。老用户首次打开时，若 users.classId 为空（迁移期兜底），自动关联到 LEGACY_CLASS_ID，无感知升级。
提交审核，等待1-3工作日
4
验证与清理
确认所有集合的 classId 字段已全部填充，验证现有用户正常使用。观察1周后，将旧 classSettings 集合归档（保留备份，不删除）。
完成迁移
🔄 回滚方案：Step 1-2 是纯增量操作（只新增字段，不修改现有数据），可随时暂停。旧版小程序（无 classId 逻辑）在迁移期间仍可完全正常使用，通过微信小程序版本管理可一键回滚。
